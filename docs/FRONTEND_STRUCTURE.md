# Frontend Structure

`BackendFailurePanel` displays the shell's startup/process failure diagnosis,
recovery steps and expandable, copyable details with the local log location.
`AppSecurityBoundary` uses this view after failed readiness or a confirmed backend
exit during lock polling; transient connection errors retain their retry flow.
Fatal failures offer a confirmed app exit rather than reloading a renderer that
cannot restart a dead sidecar. This presentation state is component-local;
Zustand's existing security error keeps all protected content hidden.

`AppSecurityBoundary` also owns the pre-database password gate. Backend snapshots
identify setup, legacy encryption, encrypted startup or an open database in the
existing Zustand `appSecurity` state. New passwords require confirmation; upgrade
uses the existing vault password. Protected children do not mount until decryption
and migration finish. The gate shows the native window itself, including backend
failure states, since `App` cannot show it before mounting. Polling remains active
during long conversion, and another window sees that work in progress. An encrypted
startup has already verified the master password, so `App` skips the old remembered
vault startup policy rather than immediately relocking the just-opened vault.

The workspace gate uses `features/security/security.css` for its responsive graphite card, scoped password focus styles, progress, error and backend-retry states. Password reveal and Caps Lock feedback are transient component state. Setup shows the existing minimum-length and confirmation requirements; ordinary unlock accepts the exact existing password without applying setup requirements.

`terminal/connectionLightning.ts` generates ten distinct electrical routes for `ConnectionBitStream`: upper/lower arcs, upper/lower forks, falling/rising crossings, a double strike, upper/lower steps and a central zigzag. Shuffled ten-form bags prohibit consecutive routes from the same family, including the visible wrap between passes, and avoid repeating a pair's previous variant. Independent seeds vary contacts along each glyph and leader/branch geometry. Resize reuses the current routes and seeds; all 47 slots remain prepared so hidden octets can reappear. Regeneration happens only on a running CSS iteration, preserving existing charge timing, afterglow, reduced motion and accelerated successful completion.

Terminal window moves use `terminal/windowHandoff.ts` and `useWindowHandoffs.ts` for a prepare/ready/commit exchange, with transient progress in Zustand `terminalTransfers`. `TerminalSessionController` owns byte checkpoints and input/resize guards; `TerminalCanvas` supplies xterm serialization/write barriers. `TerminalDockTarget` publishes actual client geometry, and `terminal/appClose.ts` unifies custom/native close policy. Full behavior, bounds and validation: [Terminal window handoff](TERMINAL_WINDOW_HANDOFF.md).

Split membership lives in Zustand `terminalGroups` (`features/workspace/groups.ts`): each group owns its pane order, layout and last focused session. The tab strip renders one group tab with a layout glyph, session count and member names; reordering, tear-out and close operate on the whole group. Ungroup restores individual tabs. Selecting an unrelated tab shows it alone and retains every group's layout. Pane selectors replace members using only ungrouped sessions; closing a pane leaves a vacancy. The empty-pane connection picker reserves the next connection for that group, while ordinary new connections remain independent. Maximizing retains group membership. Groups are transient and a fresh window starts in Single mode; the last layout choice remains a non-sensitive exported preference.

Choosing columns, rows or grid on a standalone session creates a group containing only that selected session. All other cells remain vacant. Changing an existing group's layout preserves only its manually chosen members and never collects other open tabs. Additional members enter through an explicit drop, pane selector or connection picker.

Selecting Single dissolves only the focused group, including a one-member group, and restores ordinary protocol tabs without changing session/controller/socket identity or focus. It clears that group's pending picker reservation. Selecting a split again starts from the selected standalone tab only. The pane maximize action uses `maximizeTerminalPane` instead and temporarily retains membership so the split can be restored.

Floating workspaces reveal the shared `TerminalTabsBar` when they contain independent tabs or multiple strip entries. Its detached callback uses `moveTerminalGroup` for a selected tab/group and the fixed native opener, without generic webview creation. Drag overlays stay inside the webview in this mode. Plain incoming tab-strip drops allocate independent local IDs through `prepareWorkspaceHandoff`; they cannot overwrite the fixed `detached` tab used by a standalone floating terminal. Window Return/close-Return serializes each independent tab/group, selected entry last to retain destination focus, and closes the source only when it is empty. A failed later return leaves all unreturned sessions in that window.

`DetachedTerminalWorkspace` renders a transferred group with its own layout controls and the existing drag-to-dock frame. Returning transfers every member in one prepare/ready/commit exchange and remaps local tab IDs while preserving focus. All members temporarily receive renderers during capture/replay, including members hidden by maximize or a smaller layout. No source member is released until all destination renderers are ready and commit is acknowledged. Detached group mutations never overwrite the main window's saved tab list.

Groups also own `paneSlots`, four stable nullable positions separate from membership. Closing/moving a member leaves that cell empty. `pendingTerminalPaneIndex` reserves the exact cell for the main Hosts picker. `PaneConnectionPicker` supplies the detached window's Choose a connection action, with saved-host search/refresh, local open-session movement, and the existing HostFormModal for new/quick connections. Manual vault unlock remains available; native remembered-password access stays main-only. Picker state is component-local and credentials remain in the existing form/controller/ticket path.

Both main and detached workspaces receive addressed dock probes for vacant cells. Main tabs use the same discovery during pointer drag; moving within the current window updates group membership without replacing a controller, and moving across windows uses the acknowledged handoff. Native floating windows can likewise target a specific vacant cell. Multi-session groups cannot occupy a single cell. The receiving workspace rechecks occupancy before preparing and retains all existing sessions if the move fails.

Incoming handoffs run through one cancellable queue per receiving window and wait for outgoing screen capture or reuse of a session still being moved. Independent opposite-direction moves may proceed after capture, avoiding a window-swap deadlock. This prevents concurrent returns from replacing each other's active renderer. An existing destination is shown/unminimized before preparation; new floating windows stay hidden until commit. Incoming transfers retain their active tab/view until completion, including store-driven shortcuts. Plain Return clears any pending connection-picker reservation and restores an independent tab; only an explicit pane placement merges it into a group.

Split pane headers expose a numbered drag grip and an individual detach button. `useTerminalPaneDrag` owns the transient pointer gesture (8px threshold, pointer capture, hover heartbeat and Escape cancellation); it uses the same addressed dock discovery as top tabs. `moveTerminalPane` sends a single-session offer, never a group offer. Local extraction uses `extractTerminalTab` to retain the existing controller and sockets; cross-window extraction removes the source member only after commit. The original pane stays vacant and its neighbors keep their positions. Dropping over an occupied Netrix surface cancels; dropping outside terminal windows opens a standalone terminal through the fixed-purpose native command. A detached group closes only after its last member leaves.

`terminal/pointerDrag.ts` supplies shared pointer capture and a caller/gesture-scoped native release fallback for trusted mouse gestures. Tabs and panes keep hover discovery active while stationary, freeze release coordinates, and abort pending discovery on Escape/unmount. Capture loss during a native mouse drag waits for release instead of cancelling immediately. Dock targets answer overlapping hover/drop requests independently while only the newest request updates the hint; old gesture-end events cannot clear another gesture. Tab final-drop resolution disables another sort until placement is settled. Pane preview rendering is limited to animation frames and the native tab card to roughly 30fps with one placement request in flight.

`SnippetFormModal` uses the registered non-trailing-slash URLs and sends only changed title/template fields via PATCH; hidden variables and host associations stay server-owned during edits. Failed saves preserve input. `HostFormModal` displays an explicit warning for saved jump routes; ordinary edits preserve them and new connections are blocked by backend policy until traversal is implemented.

Files async callbacks are scoped to their originating view. Host changes abort pending view requests, reset interrupted listings to `idle` and allow reload on return. Preview reads have their own cancellation identity, so closing or replacing a preview ignores late completion. Transfer cancellation does not enqueue a new directory request for the departed host. Confirmed mutations already sent are allowed to settle and invalidate the original listing, while their callbacks leave a different view's preview/actions intact.

`SftpBrowserState.connectionKey` binds cached entries/selection to public connection parameters via `features/sftp/api.ts::sftpTargetKey`. Address/port/username/protocol/credential-link/jump-link changes discard stale paths and reset navigation to home; name/group/theme/font changes do not disturb the current view. No plaintext secrets are included in this key or stored in Zustand.

`SftpBrowserState.selectedEntries` tracks remote multi-selection; `selectedEntry` is present only for one selected item. Legacy single-entry updates synchronize the collection. `FileList` supports Ctrl/Command toggles, Shift ranges and Ctrl+A within visible rows without mouse focus collapsing the collection; filtering prunes invisible selection. The local upload pane retains single selection. `useTransfers.downloadMany` snapshots the requested files, picks a folder once when supported and performs bounded sequential downloads under one view-scoped cancellation controller. Failed jobs/local writes stop the queue. Growth warnings are shown separately from failures in transfer history.

The frontend is a React 18 + TypeScript + Vite application in `frontend/`.

## State Management

Zustand stores hosts, selected host, snippets, tabs, terminal instances, WebSockets, session IDs, tab statuses, settings, group state, SFTP state, vault state, recent connections, network-map state, toasts, and confirmation dialogs. Vault state includes a separate `vaultStatusLoaded` flag so the UI never treats an unknown startup status as a clean, uninitialized Vault.

Persisted localStorage keys include settings, view preferences, collapsed groups, defined groups, terminal layout, sidebar state, the non-sensitive first-run guide completion flag, and synthetic terminal tear-out preview metadata. Credentials, terminal command history, and actual terminal output rows must not be stored in localStorage.

TerminalCanvas keeps recent commands only for saved Quick Actions explicitly submitted from Netrix. Raw terminal input and screen contents are never collected for history, including Enter after an inserted action; legacy persisted history is removed without importing it. The shared main/detached renderer applies the same policy to launcher suggestions and CSV export. Terminal input is forwarded unchanged, including the former `devtool` prefix; the dedicated Local DevTool Runner remains under Utilities.

## API Access

- `getBackendPort()` calls Tauri `get_backend_port` and caches the result.
- `getApiToken()` calls Tauri `get_api_token` and caches the token.
- `authenticatedFetch()` injects `X-API-Token` and retries once after token refresh on 401/403.
- JSON endpoints use `fetchJsonOrThrow<T>()`, which rejects non-2xx responses with the backend `detail` and permits opt-in retries only for idempotent methods.
- Raw authenticated responses are reserved for binary/header-sensitive flows such as SFTP upload/download. Transfer progress is polled from backend jobs; HTTP upload percentages are not used as remote-write progress.
- Terminal WebSockets use the `netrix-token.<token>` subprotocol.
- Quick-connect terminals first request a one-time ticket over authenticated HTTP and then open `/ws/quick-connect?ticket=...`.

## UI Patterns

- Components are functional React components with hooks.
- Tailwind classes carry most styling.
- The visual style is a dense desktop operations interface with dark terminal-oriented surfaces.
- xterm.js terminal instances must be disposed when tabs close. Once opened after bootstrap, the main Terminal view stays mounted and is hidden during module navigation, retaining its selected pane renderers, scrollback, selection and search state. It sits outside the lazy modules' Suspense boundaries so their initial loading cannot tear down xterm layout effects. Restored tabs remain dormant until Terminal is first opened. Navigation does not replay output or restart entrance animations; terminal/hint shortcuts ignore other modules. Tab-strip and Quick Action controls unmount while hidden to dismiss their portals.
- `TerminalSessionController` sends heartbeat control messages and treats backend `__JSON__` pong responses as connection health, not terminal output.
- TerminalWorkspace displays up to four xterm surfaces and retains each previously displayed TerminalCanvas under the same keyed parent until its tab closes or a window handoff releases it. A component-local set tracks visited tab IDs and prunes closed tabs; unvisited sessions stay unmounted. Hidden surfaces use `display: none`, retain their last dimensions and keep parsing live output into the same normal/alternate buffers, parser, cursor, scrollback and selection. xterm pauses invisible rendering through its IntersectionObserver; ordinary tab switches never reconstruct state from the controller's bounded 2 MiB replay. Retention uses memory per visited session; scrollback remains bounded by the user's configured line limit, and close releases the renderer/controller/socket.
- `TerminalLayoutControl` is a responsive radio group with layout diagrams, a moving selection indicator and arrow/Home/End navigation. Single, columns, rows and grid layouts, pane replacement and maximize/restore preserve renderer identity. Explicit grid positions keep pane slots correct independently of tab ordering; only visible surfaces expose `data-terminal-pane` and pane controls. Empty panes open Hosts through the existing connection picker callback. Pane close actions honor disconnect confirmation; layout/pane actions lock during window transfers. TerminalCanvas subscribes to its own terminal instance so a neighboring mount/close cannot clear selection or rerun search. Search/launcher state survives tab switches and regains focus on return, while workspace controls retain their focus. Global terminal/hint shortcuts target the active pane. The same retention policy applies inside DetachedTerminalWorkspace; cross-window moves still use the existing snapshot/checkpoint transaction.
- Detached terminal and map windows communicate through Tauri events.
- Every newly detached terminal, including a single tab or extracted pane, opens `DetachedTerminalWorkspace` with `workspace=true`. It shares the main workspace's Single, Side by side, Stacked and 2 Ã— 2 controls, a local empty-pane connection picker, and Quick Actions for the active session. A one-session handoff stays independent until the user chooses a split.
- `useTerminalWindowDrag` owns detached title gestures and cancels stale work by gesture identity. `DetachedTerminalFrame` renders the compact live surface against a transparent native background; TitleBar presents controls. `TerminalDockTarget` measures the real strip and exposes an insertion caret; neighbor placement travels in the in-memory handoff offer. `TerminalWindowPreview` is the metadata-only, non-focusable tear-out card; it uses no terminal output or persistent preview cache. See [Terminal window handoff](TERMINAL_WINDOW_HANDOFF.md).
- After the first successful main-window bootstrap, Netrix shows a one-time welcome guide when the backend reports a clean, uninitialized Vault. The guide explains the local-first model and creates/unlocks the Vault in place through the existing store action, with master-password confirmation and the shared minimum-length validation. It also gives direct navigation to each workspace. Only the guide completion flag is stored locally; Vault status remains backend-authoritative and password fields remain transient component state.
- Once initialized, a locked Vault produces a persistent main-window notice on every view except Security settings, where the unlock form is already visible. Unlock actions in the notice and navigation rail open the same focused password dialog and keep the current workspace visible.
- The persistent notice is a `shrink-0` sibling of the `min-h-0 flex-1` view slot. Full-height pages, especially Terminal and Files, must stay inside that slot so temporary notices never push bottom tabs or action bars outside the window.
- The navigation rail keeps **Help & Getting Started** available after onboarding so users can reopen the workspace map and Vault explanation at any time.

## Frontend Standards

### NetMap interactions

NetMap uses a searchable device explorer, SVG canvas and selection inspector. Compact windows use dismissible panels; focus/fit use the unobscured canvas area. Zoom is derived from the actual SVG scale, bounded by zoom controls to 10â€“500%; fitting may zoom farther out for large maps. Canvas resizing preserves screen coordinates so opening an inspector during a drag cannot move the device unexpectedly. Window-level release/blur finishes dragging; selection clicks do not persist coordinates.

Connection fields are local drafts with explicit Save/Reset. Draft patches survive changing selection within the current map and failed saves, but clear on map changes or leaving the workspace. Only changed fields are submitted. The existing API treats null update fields as omitted: clearing a label sends an empty string, and clearing waypoints sends the JSON string `[]`. Device appearance changes are applied only on Save. Ping status is separate from user-assigned accent colors and describes ping response, not SSH availability.

Undo restores the last ten successful device/link deletions within the active map. Device snapshots include incident links and all persisted link properties. Restoration uses existing authenticated create endpoints, remaps newly assigned node IDs in older history, and checkpoints acknowledged writes so partial failures can resume. This is session-local recovery, not a backend transaction or persistent undo journal; switching maps clears history, and an unacknowledged network response cannot be made idempotent by the frontend alone. Map deletion itself is not included.

Keyboard controls: V/H/C/A select, pan, link and place; Space temporarily pans; Ctrl+F searches, Ctrl+Shift+F fits, Ctrl+Z undoes deletion, G toggles snapping and M toggles the overview. Editing fields and dialogs suppress destructive canvas shortcuts. Panes and dialogs retain visible keyboard focus.

### General standards

- Keep TypeScript strict.
- Prefer typed interfaces near the owning feature or in `store.ts` for shared state.
- Use existing store actions instead of duplicating API state in unrelated components.
- Keep quick optimistic updates reversible where backend persistence can fail.
- Keep API snake_case compatibility with backend DTOs; map locally only where an established interface already does so.

## Risks and Maintenance Notes

- `App.tsx`, `TerminalCanvas.tsx`, and `store.ts` remain large and stateful despite extracting transport and network-map helpers.
- Automated coverage includes API/readiness, store, terminal-controller, and network-map helper tests plus a Windows desktop startup smoke test; broad component workflows still need coverage.
- Production Vite config drops `console` and `debugger`, so do not rely on console output for user-visible behavior.

## Terminal wire ownership

Connections is a lazy-loaded workspace with feature-local panels under `features/connections/`: Keys & identities, SSH config import, encrypted backup/restore, Known Hosts and SSH tunnels. Secret form fields stay transient and clear after success/unmount. Lists expose public metadata only. Credential assignment refreshes saved hosts; it applies on new connections. Backup restores require a typed phrase and reload the workspace after validating bounded primitive settings and restoring group/layout preferences. Terminal output, session IDs and secrets are excluded from frontend persistence.

Files offers a LocalFilePanel next to the remote listing. It performs authenticated read-only local browsing and fetches a selected file for the existing explicit SFTP upload flow; directory/file requests are aborted when the host/panel changes. The upload action displays its target and requires confirmation before replacing a listed regular file.

terminal/wire.ts is the common binary input encoder for keyboard input, clipboard, Quick Actions and Broadcast. TerminalSessionController.send sends binary data; sendControl sends JSON text. The controller streams binary output through TextDecoder so split UTF-8 remains intact. A replay_start clears retained output and queues an xterm reset before replay bytes. Old socket close/error events are ignored before touching current state or heartbeat timers. Quick-connect credentials are retained only for the same destination, and explicitly supplied new credentials take precedence.

TerminalSessionController reconnects every known session through `/ws/sessions/{sessionId}`, including Quick Connect; window handoff adds its byte checkpoint. It rejects a `connect` response with a different ID or a non-safe integer. A `session_unavailable` error retains the old ID/output, stops automatic retries and exposes **Start new session**. Only that explicit retry clears the ended identity and creates a fresh connection. `initialSessionId` is a constructor seed, so subsequent React configuration cannot restore an obsolete ID after replacement. Main and detached TerminalCanvas share this behavior.

`removeTerminalTab` returns `Promise<boolean>` and uses one confirmed-close path for tabs, split panes and detached windows. It stops the controller/reconnect timer, sends best-effort WebSocket termination and authenticates an independent DELETE by exact session ID (`terminal/closeSession.ts`, two retries, 20-second HTTP deadline). Zustand `terminalClosures` keeps pending/failed tabs visible; failure offers **Retry closing** without reconnecting or discarding the terminal view. Successful acknowledgement disposes the controller/renderer and removes the tab. Explicit `preserveSession: true` handoff release remains immediate and never deletes the shared backend session. Controllers acknowledge `connect` with `ready` after storing its ID; late callbacks after closing cannot acknowledge an orphan connection.

`features/sftp/` owns typed job APIs, sequential file upload scheduling, download validation/saving, confirmation/input dialogs and transfer history/cancellation. SftpBrowser exposes mkdir, rename, delete and chmod, with per-host back/forward directory history. LocalFilePanel has independent local history. Closing/switching Files aborts client requests and explicitly cancels the corresponding backend jobs. See [SFTP implementation](SFTP_IMPLEMENTATION.md).

`FileList` and `FilePathBar` provide shared local/remote navigation, filename filtering, dotfile visibility and natural sorting with folders first. Remote columns adapt to the pane width using scoped container queries in `features/sftp/files.css`; full metadata remains available in the File details dialog. Filter/sort/display state is transient component state. Filtering out a selected entry clears its selection before another file action. Keyboard navigation supports arrows, Home/End, Enter and Escape; remote rows also expose F2 rename and Delete confirmation, and Ctrl+L focuses the path of the active pane. Directory history seeds from cached locations, and failed navigation retries the attempted path.

The remote action bar stays available when LocalFilePanel is open. Upload/mutation actions require a ready directory; the authenticated read-only local panel explains the 128 MiB upload limit before fetching an oversized file. File dialogs retain invalid input with inline errors and initialize chmod from the selected item's permissions. Preview and details use Headless UI dialogs for focus trapping, restoration and Escape dismissal. The transfer drawer sits below the file panes, can collapse, shows active jobs ahead of recent history, and clears finished rows only from the current mounted view. No API, filesystem permission or transfer-limit expansion is involved.

Hosts requests live in features/hosts/api.ts and actions.ts, composed into the existing Zustand store. App bootstrap, Hosts views and Connections refreshes use one deduplicated loader. Mutation epochs prevent stale list responses from replacing saved edits; obsolete loads retry against current state. Per-host mutation queues serialize rapid changes. Saves consume the returned record instead of refetching the whole list. Failed/uncertain mutations reconcile without optimistic whole-list rollback.

The decoder whitelists public fields, strips unexpected secrets and normalizes nullable fields. HostFormModal builds a field diff against its original profile/revision while preserving vault-gated request/context checks; conflicts keep typed input visible. Terminal and drag/drop settings patch only changed fields. Live terminal connection snapshots retain their actual transport parameters; only saved names/appearance propagate to existing tabs. Host filtering and group trees are memoized. Group helpers share canonical path rules; cards distinguish an 8px drag threshold and support Enter/Space activation.

The Hosts error banner allows retrying list loads while keeping saved profiles visible. Local-shell argument lines preserve spaces and empty arguments, and unchanged edits preserve the original argv array. Inactive protocol fields are omitted from profile patches.

`HostFormModal` uses a Headless UI dialog with focus trapping, Escape dismissal, a scrollable body and persistent actions. Scoped styles live in `features/hosts/hostForm.css`. Protocol/authentication radios and native group/theme/baud selects support keyboard navigation. Endpoint validation is shared by Save and Connect only; Quick Connect retains the primary Enter action. Password generation and terminal appearance (with a live sample) are disclosures. Private-key file reads are bounded to 1 MiB and guarded against closing, switching hosts/protocols or changing authentication while a read is pending. Vault-gated saves freeze the queued form until users unlock or return to editing.

`TerminalColorControl` provides independent background/text presets, a native picker, HEX input and per-color reset. Host color overrides persist through the existing revision-aware API and Quick Connect descriptor. `getThemeColors` resolves overrides without mutating the shared ANSI palette; the terminal renderer, surrounding canvas and preview use the same resolved colors. Saved-host updates propagate colors to existing tabs without reconnecting their transports.

Hosts uses one `HostCollection`/`DraggableHostCard` renderer for List, Compact and Grid. List is the default when no layout was saved; scoped container queries hide secondary columns as the pane narrows and retain the endpoint under the name at the smallest width. Protocol colors identify connection types, not connection health. Card actions use a keyboard-accessible Headless UI menu, with Files directly available for SSH. `MoveHostDialog` offers an explicit alternative to dragging and uses the existing revision-aware host patch action; failed moves keep their destination and error visible.

`ConnectionStatusPanel` presents terminal connection, failure and vault-unlock states separately from `TerminalCanvas`. A compact header contains the host and one protocol/user/destination line. The main column holds the single status message, recovery actions and expandable full diagnostics; `ConnectionBitStream` supplies a decorative six-octet activity animation alongside it. A sequential electrical discharge passes between adjacent randomized bits. `terminal/connectionBits.ts` generates six distinct octets on mount and on each running sweep boundary: every octet changes at least three digits, differs from its peers by at least three digits, and avoids all values from the previous pass. Both text layers update together, then a layout effect re-anchors the discharge to the new glyphs before paint. Resize, stopped and completing states retain the current bits. A ResizeObserver measures visible digit positions and builds a separate irregular SVG bolt for each neighboring pair, including octet gaps. One CSS clock drives each bolt's brief leader, return stroke and decay; the receiving digit charges only after the leader reaches it, while earlier digits retain a fading afterglow and slight scale response. Wider gaps get a longer charging interval and longer bolt; the cadence within an octet stays consistent when the pane narrows. Hidden digits do not participate, and the last charge fades before the first bit starts again. Each completed CSS animation iteration generates new bends, branch placement and contact offsets for the next pass, while keeping charge timings unchanged; resizing retains the current variation, and paused or completed states do not regenerate bolts. No per-frame React updates or random timers are used. On failure the sweep pauses, while stop-only CSS transitions dissipate the stored charge: the core/contact/branches fade over 220 ms, the outer bolt halo over 520 ms, and digit afterglow/scale over 850 ms. The ambient field dims over 900 ms. Stopped screens retain only the unlit digits; retries remove these transitions and restore the running effect immediately. Reduced motion disables cooling transitions and hides the discharge. It is not captured traffic or measured progress. There is no duplicated stage card, status badge or branding footer. Container queries stack the activity below the message in narrow panes and prioritize the vault form over decoration. Progress remains indeterminate with elapsed attempt time; recognized controller phase events are shown once, with no simulated percentage or completed network stage.
